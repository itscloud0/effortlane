# Operations and compatibility

## What Auto actually does

`Effortlane Auto` is a picker alias, not an executor model. On each new routed interactive CLI user turn, the local policy checks the model allowlist, a bounded task excerpt, risk floor, prior route lease and context/cache hints. Under the default `completion_v4` policy, Jev answers two typed questions in one call: work shape (`mechanical`, `routine`, `substantive`, `unknown`, or `frontier` when Astra is allowed) and reasoning effort (`low`, `medium`, `high`, or `xhigh`). Local code maps the work shape to an eligible concrete model, validates capabilities and applies the switch guard. Codex then executes the whole turn with that model, its native instructions, full conversation and existing ChatGPT login. Tool calls within the turn do not trigger another route. `codex exec` routes its initial prompt before launch.

With `completion_v4`, Auto remembers only the previous work-shape category and native route for one hour. A bare "continue" or "продолжай" in the same routed CLI task can reuse that route without another Jev call if the model remains allowed and no concrete-model switch or effort override occurred. New or mixed instructions use the normal routing policy. No task text, source, or tool output is stored in the route lease. This saves a Jev call and preserves model affinity; it does not establish Pro allowance savings. `effortlane report` counts `continuation_lease` and `cache_hysteresis` decisions under `routes.reasons` and v4 work-shape categories under `routes.by_policy.completion_v4.work_shapes`.

An explicit concrete model bypasses Auto. In CLI Auto, Jev chooses **both** model and effort; the visible alias effort is not the executor effort. For a fixed effort, use `effort_policy=fixed` in router config or choose a concrete model. If the task excerpt is unsafe or unsuitable to send to Jev, the router uses Sol without calling Jev (`privacy_fallback`). In Shadow, the picker effort applies to the real Sol executor; Jev still independently proposes both model and effort, without seeing or being constrained by that picker choice. Shadow defaults to medium when no effort is selected, or the closest supported level if medium is unavailable. This is **model/effort routing**, not automatic subagent orchestration.

Jev does not choose whether to spawn subagents or assign their models. Without a separate Codex subagent setting, a child inherits its parent's model and effort. [Codex supports personal custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents) in `~/.codex/agents/`; optional [explorer](../examples/agents/explorer.toml) and [mechanical](../examples/agents/mechanical.toml) examples use Luna/high for bounded searches and edits, while [routine](../examples/agents/routine.toml) uses Terra/medium for isolated routine engineering. They must be explicitly selected by the parent agent or guided by global `~/.codex/AGENTS.md` instructions. For bounded roles, prefer `fork_turns: "none"` and a self-contained task, or a small positive number of recent turns if needed: Codex's default full-history fork copies the parent conversation and can waste context. Do not set every child to Luna: substantive implementation and debugging may need Sol, and extra agents add their own context cost. No per-repository files are required for personal agents.

For long tasks, keep the main executor on its route lease and delegate only independent, bounded work with a clear owner; this avoids repeatedly moving the full conversation between models. Keep parallel children modest on memory-constrained Macs, and verify their changes in the parent. Use Desktop when its visual tools or parallel worktrees help, and CLI for focused tasks where the app UI adds no value. The native Codex TUI also routes before each turn through a local app-server bridge. Use CI for deterministic checks, not as an assumed substitute for locally authenticated Codex execution.

For context efficiency, keep global guidance short, use bounded searches to find task-relevant files, and read sections only when needed. Preserve decisions and verified state in a handoff when moving to a fresh task; recheck that handoff against the live working tree. This uses Codex's native tools and compaction rather than pushing full repositories into Jev or adding a background indexer. It is a workflow policy, not an automatic semantic retrieval engine, and has not been shown to reduce tokens on its own.

The router does not manage Desktop's renderer, Computer Use workers, or per-thread MCP processes. On a 16 GiB Mac, one live investigation found hundreds of Desktop descendants and swap near full while the router itself remained small; this resembles [Codex issue #44996](https://github.com/openai/codex/issues/44996) and [#46799](https://github.com/openai/codex/issues/46799), but the exact cause on that Mac is unproven. Prefer CLI for focused tool-heavy work when Desktop's UI is unnecessary, close idle Desktop tasks, and inspect the process tree before disabling a plugin. Do not delete persisted session data to treat an active process problem.

When the Desktop wrapper is active, Effortlane Auto advertises one visible effort; the router chooses the actual executor effort. Effortlane Shadow exposes Sol's supported efforts and applies your selection to the real executor. With the wrapper disabled, Desktop uses its native concrete picker. Use `effortlane report` and `effortlane trace THREAD_UUID` for routing evidence.

The adapter changes only Codex app-server model/effort commands. Built-in tools such as image generation are separate calls; an image-tool HTTP error is not a route decision. Check the tool's own result before attributing it to this router.

If built-in Image Gen returns an immediate empty-body HTTP 404, changing Jev's model/effort policy is not a demonstrated fix. On one affected Mac, the same minimal request failed under Effortlane Auto and concrete Sol/Astra, and still failed while only the local daemon was stopped. After disabling the Desktop adapter **and** restoring native global Codex config, then fully restarting Desktop, the same request succeeded twice. This established an integration regression on that Mac, but did not isolate the adapter from the former global `openai_base_url` override. New installations no longer set that global URL; existing installations migrate it away on `disable` then `enable`. After a second full Desktop restart with the updated config and adapter active, Effortlane Auto routed a native Sol/medium turn and the same built-in Image Gen request succeeded. This validates that combination on the affected Mac; other environments should still test after upgrading. The [Codex issue reporting the same error](https://github.com/openai/codex/issues/43250) may have another cause. The optional OpenAI Image API is a separately billed path and is not enabled by this router.

Jev has a four-second socket timeout by default. A timeout is recorded as `jev_timeout` and falls back to Sol; other provider failures are `jev_error`. The longer timeout avoids discarding valid decisions from occasional 2–4 second responses, at the cost of waiting up to four seconds on a failed call. A running CLI bridge needs a new CLI session to load Python code updates.

Effortlane holds the shared lease-file lock only while reading or committing state, not while waiting for the decision service. Concurrent chats can therefore route independently. Same-session requests use one of 256 fixed lock stripes, with a cumulative 250 ms lock-wait budget; a stripe collision or busy state file still fails open. Commits merge into the latest state and reject stale same-session decisions. Metered decision-service tokens remain recorded even when a commit fails. Older running adapters still use the previous locking behavior until their clients are reopened; installation does not interrupt active work. This fixes a reproduced concurrency failure, not a demonstrated cause of historical allowance consumption.

To see what happened on one task, run `effortlane trace THREAD_UUID`. It shows the logical picker alias, actual executor, route reason, Jev latency and token metadata without printing prompts or source. A `concrete_model` reason on later usage events describes the native executor call; it does not mean a preceding Auto route was manual. The aggregate `effortlane report` cannot establish quality-equivalent savings or ChatGPT Pro allowance debits.

## Install and controls

The one-command download installer is documented in [Quick start](../README.md#quick-start).
It uses the same `bootstrap.py` and existing prerequisites. A second run checks
an existing installation without resetting settings or updating source. For a
reviewed source version, set `EFFORTLANE_REF` on the shell running `install.sh`;
the default is the current `main` branch. The installer neither changes shell
profiles nor installs/login native clients. A fresh installation retains the
existing Auto default; use the explicit Shadow launch shown in Quick start to
evaluate first.


Fresh macOS CLI setup (Python 3.11+, native Codex already installed and signed in):

```sh
git clone https://github.com/itscloud0/effortlane.git
cd effortlane
python3 bootstrap.py
```

The bootstrap fetches the authenticated model catalog, asks for the TypeSafe/Jev key with hidden input only if no owner-only key file exists, backs up Codex config, and installs the owner-local router. It does not change Desktop's executable or its model picker. It refuses to replace an unrelated `~/.local/bin/codex`; if that directory is not first on `PATH`, it prints the one remaining shell action. Use `python3 bootstrap.py --key-file /absolute/path/to/owner-only-key` for non-interactive setup. Review `bootstrap.py`, `manage.py`, `core.py`, and `transport.py` before running remote code.

Existing/manual setup and controls:

```sh
/opt/homebrew/bin/python3 manage.py install --execution-binary /Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex --key-file /absolute/path/to/owner-only-typesafe-key
effortlane status
effortlane report
effortlane savings --hours 168
effortlane evaluate --hours 24
effortlane trace THREAD_UUID
effortlane desktop-enable
effortlane desktop-safe
effortlane desktop-disable
effortlane disable
effortlane enable
effortlane rollback
```

Install backs up `~/.codex/config.toml`, preserves the Desktop root model, effort, model catalog, and any original `openai_base_url`, adds a user LaunchAgent on `127.0.0.1:43191`, and replaces `~/.local/bin/codex` with a symlink to the wrapper. By default, the CLI wrapper uses the selected Desktop bundled Codex binary. `effortlane cli-set-native --native /absolute/path/to/codex` can point terminal execution to a separately installed CLI; it backs up the manifest and leaves Desktop on its signed bundled binary. `~/.local/bin/codex-native` is an explicit bypass shim and uses the CLI target with the native endpoint and catalog. If the configured CLI target disappears, terminal commands fall back to the Desktop binary and `doctor` reports the stale path. The prior `codex` symlink remains recorded for rollback. Owner-only files live in `~/.local/share/jev-codex-router`. No app bundle is modified. A fresh install defaults CLI to Auto; setting the global Codex model to `jev-shadow` makes plain CLI and Desktop Shadow until changed back.

## Policy configuration

Edit `~/.local/share/jev-codex-router/config.json` (owner-only), then restart the relevant Codex process to load code changes; ordinary policy values are read at each new route. `effortlane status` shows the effective policy. Example values:

```json
{
  "auto_roles": ["luna", "terra", "sol"],
  "auto_policy": "completion_v4",
  "large_context_sol_floor_tokens": 48000,
  "shadow_policy": "completion_v4",
  "effort_policy": "jev",
  "fixed_effort": "medium"
}
```

`auto_roles` is the executor allowlist and must include Sol. Add `"astra"` to let Jev choose Astra automatically, without a confirmation window; the default excludes it. Jev chooses only from roles available in the authenticated Codex model catalog and permitted by this list. Auto excludes a weaker role when the dated Codex credit rate card shows Sol is no dearer for uncached input, cached input, and output; currently this removes GPT-5.6 Terra when GPT-6 Sol is available. `effortlane status` shows `effective_auto_roles`. Set `"allow_dominated_roles": true` to retain an allowed role for a measured latency or quality reason. Update the rate card as prices change. High-risk work has a Sol floor and at least high effort; Jev may upgrade it to Astra when Astra is allowed. If Jev fails, the route falls back to Sol rather than spending Astra. `effort_policy` is `jev` or `fixed`; `fixed_effort` accepts `low`, `medium`, `high`, `xhigh`, `max`, or `ultra`. A concrete model choice overrides routing and the allowlist. An explicit CLI effort flag can still constrain a CLI Auto launch.

`large_context_sol_floor_tokens` defaults to 48,000. Under v4 it marks a context where switching away from a stronger model needs three consecutive, distinct Jev recommendations for the same cheaper role. A measured cached-input ratio of at least 80% triggers the same guard even below that size. It does **not** remove Luna/Terra from Jev's choices. Failed, invalid, or `unknown` decisions reset the streak; capability upgrades happen immediately. Set the threshold to `0` to disable the context-size trigger, while the cache trigger remains. Earlier policies still use this setting as an absolute Sol floor. The three-turn guard is a conservative heuristic, not a calibrated optimum; compare correction and retry rates before claiming savings.
The Desktop adapter tracks concrete-model overrides when the experimental wrapper is active.

`auto_policy` and `shadow_policy` each accept `baseline`, `completion_v1`, `completion_v2`, `completion_v3`, or `completion_v4`. New installs default both Auto and Shadow to v4: one TypeSafe call with up to two independent Choices, work shape and reasoning depth. Deterministic code maps work shape to available model roles, applies the risk floor, allowlist, and cache-aware switch guard, and sends an explicit `unknown` shape to Sol. `xhigh` on Luna/Terra upgrades to Sol; an explicit CLI effort override remains binding. Shadow executes the newest Sol visible in that client's authenticated native catalog and records what the same v4 policy would have selected. The Shadow effort picker controls only the executor. If the Desktop bundle and independent CLI expose different Sol versions, they execute different Sol versions until their native catalogs converge. Earlier v3 used an absolute long-context Sol floor; this prevented cheaper roles from being considered on 22 of 24 observed Desktop Auto turns, which is why v4 replaces it. V4 passed unit tests and a three-turn live Jev smoke on a mechanical task, but has **not** established quality-equivalent savings. All policies keep Jev's input bounded and omit source/tool output. These policies adapt ideas from [0xNatoshi/jev-codex-router](https://github.com/0xNatoshi/jev-codex-router) and [auto-codex-router](https://github.com/zhangqiang8vipp/auto-codex-router) under their MIT licenses; no source module was copied.

`unknown` means the bounded current-turn text does not establish the work shape. It is expected for short references to earlier turns and requests whose substance is in an image or omitted code; Jev does not see full history or attachment contents. When the allowlist and deterministic risk floor leave only Sol eligible, v4 asks only for effort and records `sole_eligible_model` under `routes.model_bases`; a Jev `low` effort is raised to `medium` when work shape was not classified. An `unknown` answer never downgrades an existing Sol lease.

CLI calls with a visible initial prompt run in auto mode by default. `--effortlane-shadow` forces the newest CLI-catalog Sol execution at your selected effort and records Jev's independent proposed pair. `--effortlane-auto` explicitly routes. `--effortlane-off` uses the native bypass. Manual concrete `-m`/`--model`, `-c model=...`, and profile choices take precedence. The CLI wrapper injects its own client-specific catalog only for that process; Desktop keeps a separate managed catalog. A routed `codex exec` also receives its native model metadata from that account catalog, avoiding Codex's unknown-model fallback for newly released Sol versions. In an interactive terminal, `codex` and `codex resume` launch the original Codex TUI via a per-process loopback app-server bridge. The CLI adapter selects a concrete model and effort at every `turn/start`; resume keeps native thread history and the launcher's Auto/Shadow intent even when the old thread echoes its concrete model. A deliberate concrete `/model` switch still wins. Explicit concrete models bypass routing, and the native `/model` picker can switch back to Effortlane Auto within the same TUI. Custom providers and `--effortlane-off` bypass the bridge. `codex-native` also opens the native TUI without Jev. `codex exec resume` retains native selection. Jev failure falls back to the newest catalog Sol; the late HTTP gateway is not used for these interactive turns.

If the global Codex `model` is explicitly set to `jev-shadow`, plain interactive `codex`, `codex resume`, and `codex exec` use Shadow by default. Its configured `model_reasoning_effort` applies to the Sol executor while Jev proposes its own effort. `--effortlane-auto` still opts into Auto, and a concrete model still wins. This is useful for a fixed-Sol measurement day without per-command flags.
`effortlane status` reports this as `codex_default.routing: shadow` with the default model and effort. Its top-level `mode` is the router's policy/kill-switch setting, so `mode: auto` can coexist with a selected Shadow alias. A model selected in an existing chat can still override the global default.

The bridge waits until its accept thread is ready before launching the TUI, then accepts only an authenticated local connection. A stray or incomplete connection is ignored; a failed startup prints the last handshake stage without prompts or credentials. `JEV_BRIDGE_DEBUG=1 codex resume` shows subsequent connection stages when diagnosing a startup failure.
The native TUI opens a separate remote app-server connection for its session picker. The bridge serves both connections with isolated native app-server children; a single accepted connection would leave `/resume` and the picker waiting until Codex timed out.

Mobile Remote and the local TUI bridge are different transports. Effortlane's aliases belong to the local RPC adapter, not to OpenAI: native app-server processes now receive the concrete native catalog; the adapter adds Effortlane Auto/Shadow only to its `model/list` replies. `codex remote-control` also receives the native catalog and a concrete default. This prevents the native Remote server from advertising unsupported synthetic models. Mobile Remote routing is **not validated or claimed**; use a concrete model there. Existing Remote frontend selections may need to be changed to a concrete model after restarting the host app.

If Effortlane disappears only in a terminal, run `~/.local/bin/codex` and check `/model`. This bypasses stale shell command lookup and an absolute native Codex launch configured by another tool. A running CLI/backend retains its startup code: installing an update does not hot-patch active sessions. Do not log out or delete session state to refresh the picker. A Desktop update may change the bundled executable path; run `effortlane doctor`, then `effortlane desktop-refresh-native --native /Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex` if it reports path drift.

The older `effortlane chat` mini-client remains available for scripted diagnostics, but is no longer the default interactive UI. It accepts `--model effortlane-auto|effortlane-shadow|CONCRETE`, `--resume THREAD_UUID`, `--last`, and `--once` (one prompt from stdin). Within the client, `/model NAME` changes the next turn and `/exit` quits. It handles command and file approvals interactively and denies them when stdin is not a terminal. Unsupported app-server client requests fail closed with a visible message. The terminal client is deliberately small: it does not reproduce the original TUI's full screen UI, slash commands, image paste, or every app-server approval/tool surface. Use the native `codex` TUI for slash commands, image paste, approvals, and other standard UI features.

Healthy CLI calls use a capability protected `/cli` gateway path so telemetry identifies the client even when Codex sends Desktop-style headers. The wrapper leaves explicit custom base URLs, providers, and profiles untouched. Route decisions and executor usage are separate telemetry events; `report` counts requests and tokens only from usage events and shows Jev latency and proposals from route events.

Routed `codex exec` launches add a random per-launch token to that loopback path. The wrapper and gateway derive the same pseudonymous route ID from it, so `report` and `evaluate` can link the route to all matching executor calls, even across telemetry rotation. The token is never forwarded to ChatGPT. Interactive CLI turns use the same random route IDs as Desktop, with `client=cli`. The late HTTP gateway cannot safely switch an original native TUI turn from Sol to Luna/Terra after Codex has built Sol's harness; `evaluate.auto_model_calls.gateway_blocks` counts these rejected proposals.

`effortlane disable` restores owned config keys and stops the gateway. `effortlane rollback` additionally restores the original `codex` symlink and removes only the installed links and LaunchAgent. Backups, routing state, and telemetry remain for inspection. Manual edits to managed keys are preserved; `status` lists their names. Re-enabling preserves manually selected model and effort, migrates the former global relay URL away, and may require resolving other conflicts. Both operations preserve unrelated config edits.

`effortlane update` accepts only a native `~/.codex/models_cache.json` refreshed within ten minutes and updates the Desktop catalog when its compatibility gate permits. To refresh the CLI independently, run `effortlane cli-refresh-models`. It asks the configured native Codex executable for the authenticated account catalog in a temporary, owner-only Codex home with a copy of the existing auth file; the copy is removed afterward. It does not update login credentials, router config, or Desktop catalogs. It backs up the manifest and atomically switches CLI to a complete catalog generation. Restart existing CLI sessions to see the new picker and routes. Check `effortlane doctor` after a Codex update.

`codex update` checks whether its native CLI target resolves to the same `@openai/codex` package under `npm root -g`. Only then does it run `npm install -g @openai/codex@latest`, which avoids the native command's installation-method error. Other installs keep the native update command. After a successful update, Effortlane refreshes the authenticated CLI catalog; on refresh failure native Codex remains usable and a short retry command is printed. It does not update ChatGPT.app. Keep the CLI target on a stable executable path (for example, `/opt/homebrew/bin/codex`) so subsequent updates need no Effortlane reconfiguration. Use `codex --version` and `effortlane doctor` afterward. Existing CLI sessions must be restarted to use the new executable; Desktop updates through the app. The package update can change native Codex behavior, so review it separately from router policy changes.

New model releases are account-gated. A model in `codex debug models --bundled` is not proof of account access. Effortlane maps versioned roles such as `gpt-6.1-sol` from the authenticated account catalog when that model appears there; it does not inject a bundled-only model. On 2026-09-30, the authenticated account catalog included `gpt-6.1-sol`, while Effortlane's older installed snapshot hid it from the CLI picker. `effortlane cli-refresh-models` fixes that CLI drift without disturbing a running Desktop adapter. The account catalog can change experimental capability flags between fetches; a repeated refresh can therefore install a new generation even when the model names are unchanged. Unknown model rates stay out of cost estimates instead of inheriting an older model's price. A fresh `codex` session shows Effortlane Auto in `/model`; `codex-native` and `codex --effortlane-off` intentionally show only concrete models.

## Report

`effortlane report` aggregates the latest 30 days of recorded model, effort, token counts, cache tokens, route switches, failures, and Jev latency. It also reports weak quality signals from Desktop: a failed prior turn, a concrete-model override after Auto, and nonzero command exits. A nonzero command exit is not necessarily a failed test or bad route. Telemetry archives are owner-only and retained rather than overwritten at each 2 MB rotation; reports read the legacy archive and newer archives. The adapter sends measured cache-read percentage, `hot`/`warming` state and age to Jev only for ten minutes after a native usage notification; no old cache reading is treated as current. To compare the observed mix against fixed all-Sol and all-Astra choices, supply your own relative weights:

For `completion_v2`, `completion_v3`, and `completion_v4`, each fresh Jev Choice yields a privacy-safe decision receipt. V2 records the selected model/effort pair's probability and confidence; v3/v4 record work shape, its probability/confidence, and effort confidence. Both record the resolved Jev model version. `effortlane trace THREAD_UUID` shows these fields beside the route; `effortlane report` shows confidence sample count and mean by policy. A cached decision retains its original receipt. Missing or malformed scores are recorded as null and never alter the selected executor. Per [TypeSafe's confidence guidance](https://docs.typesafe.ai/confidence), confidence is **not** a correctness probability or a calibrated routing threshold: it measures concentration of Jev's offered choices. Mean confidence across v2/v3/v4 cannot be compared as quality because their choice sets differ. Calibrate any future numeric gate against observed task outcomes, including corrections and retries, before letting it change Auto. V4 uses the same Jev questions as v3; its switch guard is deterministic.

New Desktop route and turn-usage records share a random 24-hex-character ID. `effortlane report` links only records with matching ID, session, client, executor model and effort, then shows completion status, nonzero command exits, prior failed turns, and observed tokens by route model/work shape/policy. This is a weak outcome view: a completed turn is not proof of correct work, a nonzero command exit is not necessarily a failed test, and native `last` usage may cover only the last model call. Old records cannot be linked retrospectively. No prompt, source, image or tool output is added to telemetry.

Desktop usage events now use the same one-way thread hash as route events, so new records can be grouped by task without storing thread IDs. Older Desktop usage events with an empty session field cannot be assigned retrospectively to a route; exclude them from task-level comparisons.

```json
{
  "gpt-6-sol": {"input": 1, "cached_input": 0.1, "output": 2},
  "gpt-6-astra": {"input": 2, "cached_input": 0.2, "output": 4}
}
```

Run `effortlane report --weights /absolute/path/weights.json`. Include weights for every observed model. The comparison holds token counts constant and is a sensitivity estimate. It does not measure Pro quota debits, quality equivalence, or money saved.

`effortlane evaluate [--hours 1..720] [--since ISO-8601-UTC]` isolates current-policy (`completion_v4`) Auto/Shadow receipts. It shows executed and proposed model counts, explicit `unknown` versus no classification, cache-held proposals, exact route-to-usage linkage, gateway-blocked downgrade proposals, and weak outcome signals by executed model. It deliberately returns `quality_equivalent_savings: null` until matched, quality-checked comparisons exist. It reads all retained telemetry archives within the requested window, but cannot recover records overwritten before this version. It never prints task text or source.

`effortlane cost [--hours 1..720]` shows all observed Auto model calls and the exact pre-turn route-to-usage subset, split by Desktop and CLI. It also shows a separate Shadow baseline: real Sol executor tokens are linked to Shadow proposals by route, session, turn, model, and effort; proposed cheaper models are **not** counted as savings. All observed model calls are shown separately; that wider total includes manual models and must not be attributed to Jev. The built-in [Codex credit rate card](https://learn.chatgpt.com/docs/pricing) and [API dollar rate card](https://developers.openai.com/api/docs/pricing) are checked 2026-09-30 and assume Standard, short-context processing. They are **sensitivity estimates holding observed token counts constant**, not measured Pro allowance savings, separately billed API charges, or quality-equivalent completion costs. The API comparison covers only models with a published rate in the local snapshot. Jev's API response contains input/output token usage, which new route receipts record; older calls lack it. TypeSafe publishes a Jev token rate, but no account billing export was verified, so the actual Jev charge remains unknown. Refresh the rate card when prices change. A meaningful savings claim needs enough linked Auto turns and reviewed outcome/rework labels.

For a short, readable view run `effortlane savings` (last 24 hours), `effortlane savings --hours 168`, or `effortlane savings --since 2026-09-28T10:59:53Z`. The last form sets a UTC cutoff, useful after an integration change. It leads with all observed Auto traffic and the share linked to pre-turn decisions, then shows the exact linked subset. This prevents a large percentage on a tiny routed subset from being mistaken for whole-workload savings. The Jev line shows metered input/output tokens and a **published-rate estimate** using TypeSafe's [$0.042/M input-token rate, with output free](https://typesafe.ai/blog/introducing-system-one-models-and-jev). Promotional credits and the actual account bill remain unknown. If there are no priced calls, the command says the difference is unavailable instead of claiming savings.

The `auto.unlinked_cli_gateway` section also counts native CLI TUI/resume traffic with Effortlane Auto selected. Its `distinct_session_turns` groups calls by hashed session and latest user turn; `by_model_calls` shows what actually executed. These calls lack matching pre-turn route receipts; they appear in the whole Auto comparison but are excluded from the linked subset. A large unlinked count may reflect sessions launched before the native CLI bridge was installed, or another path that did not record a receipt; inspect a fresh session before attributing it to the current integration. Older telemetry may have been overwritten before archive retention was added.

For a small human-reviewed sample, `effortlane trace THREAD_UUID` exposes the random route ID. Put one local JSONL record per reviewed route in an owner-only file, for example `{"route_id":"0123456789abcdef01234567","outcome":"accepted"}`. Allowed outcomes are `accepted`, `rework`, and `failed`; these describe the *observed executed route*, not a hypothetical cheaper model. Run `effortlane evaluate --hours 168 --labels /absolute/path/labels.jsonl`. Only labels for exactly linked turns in the window count; unrelated fields are ignored and never echoed. Do not put prompts, source, or secrets in label files. These subjective labels still cannot prove an all-Sol or all-Astra counterfactual. A proper savings claim needs comparable real coding tasks, acceptance checks, full-turn usage and rework tracking.

To evaluate a new integration, note its UTC installation time and run `effortlane savings --since TIMESTAMP` and `effortlane evaluate --since TIMESTAMP`. Do not mix existing long-lived TUI processes with new bridge launches; restart those sessions or resume them through a newly launched `codex --effortlane-auto resume THREAD_UUID`. The `--since` filter excludes old receipts but cannot change the behavior of processes already running before the update. For a quality comparison, alternate comparable real tasks between `codex --effortlane-auto` and explicit `codex -m gpt-6-sol`, record the full session IDs and elapsed time through accepted tests/review, and count all retries and rework. Label routed turns with `trace` and `evaluate --labels`. Compare credit-equivalent usage **per accepted task** only after checking that quality and time-to-accept did not regress. A same-token model-price calculation alone is not proof of Pro allowance savings. Jev's actual charge remains unknown until a TypeSafe billing export is available.

The [Keel decision architecture](https://github.com/codejunkie99/keel/blob/3fc24b0ee3eff8938dde33c90bbf93125bc4e804/docs/decision-architecture.md) supports host-validated choices and explicit receipts, but its in-loop tool control applies to its own embedded agent, not Codex's internal loop. The [Jev alignment-detection study](https://arxiv.org/pdf/2609.29429v1) evaluates error detection rather than coding model routing. Its 63× figure compares detector costs with LLM judges; it is not a Codex Pro savings estimate. We do not use its probabilities as uncalibrated routing thresholds.

## Limits

The catalog alias is cloned from Sol only for picker compatibility. The CLI app-server adapter resolves the concrete model before native turn construction for the original CLI TUI, so the executor uses its own model instructions and tools. For older clients without the adapter, the HTTP gateway retains a compatibility gate and executes Sol when target metadata differs. `codex exec` selects a native model at launch.

The Desktop adapter uses the undocumented `CODEX_CLI_PATH` override. The first Python-parented version broke `codex_app`. The new bootstrap spawns a sidecar and `exec`s signed bundled Codex in Desktop's child PID, preserving the expected native process ancestry. A live restart confirmed `codex_app` initialization; a minimal Image Gen call from the agent runtime also succeeded. Scheduled tasks, Chrome and Computer Use still need direct Desktop feature tests. `desktop-safe` removes the managed override and alias catalog; fully quit and reopen Desktop afterward. A configured `hostConfig.codex_cli_command` takes precedence. Presence of picker aliases or an environment setting alone does not prove the running app adopted the wrapper.

The Desktop wrapper adds a command-line override for the official ChatGPT Codex URL. Its sidecar records allowlisted token counts from native `thread/tokenUsage/updated` notifications. If bootstrap setup fails, it runs native Codex without routing. Interactive CLI uses a short-lived, bearer-protected `127.0.0.1` WebSocket bridge to a native app-server; it keeps the original TUI and does not use the Responses relay. The one-launch token is never printed or stored. `codex exec` still uses that relay for telemetry and can be interrupted if it dies mid-request.

`effortlane status` includes `desktop.runtime.adapter_active` and `direct_native_app_server`, determined from the primary Desktop process's direct children without printing process arguments. This excludes standalone probes launched inside a Codex task. In native Desktop mode, expect `adapter_active=false`, `direct_native_app_server=true`, and `auto_routing_active=false`. After a Codex update, run `effortlane cli-refresh-models`, `effortlane desktop-refresh-models`, and `effortlane doctor`. The Desktop refresh asks its **own bundled binary** for a fresh authenticated account catalog, validates that it can load the generated aliases, backs up both installed catalogs, and atomically replaces each owned file. It leaves `~/.codex`, the user's model selection, sessions, and `CODEX_CLI_PATH` unchanged. It refuses a manually modified catalog; a second run with the same catalog changes nothing. Fully quit and reopen Desktop to load the new picker metadata. Doctor checks both executable paths, alias metadata, and the local gateway; it compares Codex's account cache only when that cache is fresh, because a stale cache may predate a catalog refresh. The read-only doctor check does not prove native execution or built-in tools; run one routed CLI turn and built-in tool smoke test after major updates.

If an app update moves the bundled CLI, `status` and `doctor` report a missing `native_target` and/or a Desktop wrapper mismatch. Once the new binary is present, run `effortlane desktop-refresh-native --native /Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`. This checks ownership and `CODEX_CLI_PATH`, backs up the manifest and wrapper under `~/.local/share/jev-codex-router/backups/desktop-native-*`, then atomically writes the new path to both files. A second run is a no-op. A manually edited or third-party wrapper is reported and never overwritten automatically. The command does not change the Desktop environment or restart the app; fully quit/reopen Desktop if its running backend still uses the old binary.

`desktop-disable` restores the owned environment and leaves CLI/relay enabled. It backs up the owned active wrapper and replaces it with a native-only launcher, because Desktop may keep using the old path even after `CODEX_CLI_PATH` is cleared. `desktop-safe` does the same for a previously disabled installation. Global `disable` and `rollback` also remove the Desktop override. A Desktop restart is required for environment changes to affect a running app. User changes to the environment or wrapper are preserved rather than silently overwritten.

Routing happens between user turns. Tool chains and active-turn steering keep their executor. Explicit concrete choices disable automatic intent. Resume with unknown context preserves a conservative native model. Unexpected adapter transform errors and app-server JSON frames over 8 MiB pass unchanged to native Codex; the legacy HTTP compatibility gate remains for clients without the adapter. Interactive CLI's WebSocket framing has a separate 64 MiB limit. Prompt contents, source, tool output and auth are never written to the adapter sidecar.

When enabled, the Desktop adapter preserves a logical Effortlane alias in thread metadata and resolves the concrete model at `turn/start`. A running Desktop process must adopt the new wrapper before this takes effect.

The relay terminates a stream after a complete response.completed SSE frame instead of waiting for upstream EOF. It allows up to 16 simultaneous requests, remains loopback-only, and preserves native bearer forwarding only to the fixed ChatGPT endpoint. WebSocket requests still use native HTTP fallback. Daemon failure can interrupt routed CLI work; Desktop app-server execution is direct native Codex. Revalidate model availability, CLI bridge behavior, and built-in Desktop tools after Codex updates.

Observed latency is recorded without clipping to the configured socket timeout; that timeout is not a strict whole-operation wall-clock deadline. No Pro savings or broad engineering-quality parity is established by the small smoke/coding tests.

### Synthetic model rejected by ChatGPT authentication

If a turn reports that `jev-shadow` or `jev-auto` is unsupported, a synthetic picker ID reached the native executor. The RPC adapter now guards native model fields, including `config.model` and collaboration settings. A routing/state exception falls back to a concrete native model while preserving the original input; custom provider requests remain untouched. Regression tests cover state failure and configuration overrides. This guard does not repair a process that bypasses the adapter entirely.

Installed code is loaded at process start. Exit and reopen only the affected CLI session, then resume its thread. An already-running adapter retains its old code. There is no need to delete history, log out, or restart other healthy chats.

### Backend logs overwrite the CLI input box

The foreground native TUI must be the sole owner of terminal output. The Effortlane CLI bridge discards the background app-server's raw stderr instead of inheriting the terminal; structured protocol responses still flow to the TUI. This avoids rendering corruption and avoids storing raw command/source fragments in an extra router log. CLI adapter fallback diagnostics stay off the active terminal, and initial connection timeout diagnostics are deferred until the foreground process exits. Explicit `JEV_BRIDGE_DEBUG=1` still prints protocol method names and is intended only for troubleshooting.

Reopen the affected CLI process to load the fix. A tool's patch-validation or command-policy failure is a separate issue: suppressing raw stderr does not make a rejected operation succeed.

### Native defaults and requests without a model

When the global OpenAI Codex model is an Effortlane alias, CLI and Desktop app-server startup now explicitly use the catalog's concrete Sol as the native default. The adapter retains the logical mode and recognizes new threads/turns that omit a model. This prevents an inherited synthetic default from reaching native execution. Explicit concrete models and custom providers/endpoints/profiles remain unchanged. No global auth or Codex configuration is rewritten.

Local image items pass through unchanged. The remote native TUI may refuse to restore a failed prompt containing local image paths; that recovery warning is a native safety restriction, not proof that image transfer failed. After a failed multimodal turn, reattach images rather than assuming the editor restored them. Restart the owning app-server to load startup changes; restarting only a frontend attached to an existing Desktop backend is insufficient.
